# MM-21: Rozliczenie jedzenia ze zdjęciami

**User Story:** Jako kierownik chcę uzgadniać pozostałe jedzenie z magazynem, aby zatwierdzać rozliczenie końca dnia.

**What to build:** Kompletny przepływ na telefonie, przez publiczne API do trwałego zapisu i ponownego odczytu.

**Blocked by:** MM-11, MM-13, MM-20

**Status:** implemented-local — rozliczenie jedzenia i utylizacja zintegrowane; natywna współbieżność i odbiór telefonu nadal otwarte.

## Kryteria odbioru

- [ ] Snapshot dnia: stan oczekiwany, rezerwacje, policzona ilość i rozbieżności.
- [ ] Rozdział ilości: pozostawienie, utylizacja, przekazanie i zatwierdzony posiłek; sumy zgodne z policzonym stanem.
- [ ] Utylizacja ma ilość, powód, zdjęcia przed/po i akceptację; opcjonalnie drugi świadek.
- [ ] Zgłoszony towar wyłączony ze sprzedaży, rozchód księgowany raz przy akceptacji; odrzucenie nie przywraca automatycznie zniszczonego produktu.

## Testy i zakończenie

Testować publiczne zachowanie API z bazą i interakcje telefonu: główny scenariusz, brak uprawnień, izolację lokalu, retry i utratę połączenia tam, gdzie wpływają na wynik. TypeScript, właściwa regresja i code-review przed zakończeniem. Etap daje samodzielnie demonstracyjny rezultat; nowe schematy i interfejsy powstają razem z obsługiwanym przepływem.

Doprecyzowanie 2026-10-16: porównanie oczekiwanego jedzenia na koniec dnia wymaga MM-11, aby rzeczywista sprzedaż trafiała do tego samego magazynu. Ręczny rejestr sam nie daje pełnego obrazu zużycia.
