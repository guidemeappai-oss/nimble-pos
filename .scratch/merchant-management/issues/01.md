# MM-01: Role kierownika i dziennik decyzji

**User Story:** Jako właściciel chcę delegować prawa operacyjne, aby zarządzać zespołem bez oddawania kontroli nad utargiem.

**What to build:** Kompletny przepływ na telefonie, przez publiczne API do trwałego zapisu i ponownego odczytu.

**Blocked by:** None (can start immediately)

**Status:** completed — lokalna implementacja, testy i code-review zakończone.

## Kryteria odbioru

- [x] Serwer sprawdza prawa per lokal do menu, rabatów, zapasów, zdjęć i raportów; cofnięcie prawa działa także dla aktywnej sesji.
- [x] Kierownik nie podpisuje wypłat; rozszerzenie ADR 0002 dokumentuje delegowanie praw operacyjnych.
- [x] Operacje zapisują autora, czas serwera, powód i zmianę wartości; korekty nie usuwają historii.

## Testy i zakończenie

Testować publiczne zachowanie API z bazą i interakcje telefonu: główny scenariusz, brak uprawnień, izolację lokalu, retry i utratę połączenia tam, gdzie wpływają na wynik. TypeScript, właściwa regresja i code-review przed zakończeniem. Etap daje samodzielnie demonstracyjny rezultat; nowe schematy i interfejsy powstają razem z obsługiwanym przepływem.

Wdrożone operacje: menu, dostępność, raport lokalu, historia i delegowanie. Uprawnienia przyszłych magazynu, zadań, zdjęć i rabatów są przygotowanym kontraktem, sprawdzanym przy wdrożeniu ich operacji.
