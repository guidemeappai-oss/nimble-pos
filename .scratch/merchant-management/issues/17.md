# MM-17: Partie i terminy przydatności

**User Story:** Jako kierownik chcę widzieć partie z bliskim terminem, aby ograniczać przeterminowanie.

**What to build:** Kompletny przepływ na telefonie, przez publiczne API do trwałego zapisu i ponownego odczytu.

**Blocked by:** MM-12, MM-15

**Status:** implemented-local — odbiór natywny i urządzenie nadal otwarte.

## Kryteria odbioru

- [x] Dostawa i produkcja zapisują partie, daty i ilości; propozycja zużycia według najbliższego terminu.
- [x] Termin generuje alert oraz decyzję, nie usuwa stanu bez ruchu.
- [x] Spis i strata wskazują partię, gdy jest śledzona.

## Testy i zakończenie

Testować publiczne zachowanie API z bazą i interakcje telefonu: główny scenariusz, brak uprawnień, izolację lokalu, retry i utratę połączenia tam, gdzie wpływają na wynik. TypeScript, właściwa regresja i code-review przed zakończeniem. Etap daje samodzielnie demonstracyjny rezultat; nowe schematy i interfejsy powstają razem z obsługiwanym przepływem.

Wynik: docs/product/inventory-lots-running.md. API337/337, web269/269, shared56/56, typy i build; rozszerzony scenariusz Chromium1/1. Przegląd spójności: cofnięcia wskazują oryginalne partie, oczekujące straty chronią przydział, przeterminowanie tylko alarmuje.
