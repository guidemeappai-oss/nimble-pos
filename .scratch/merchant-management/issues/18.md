# MM-18: Lista zakupów i zamówienia dostaw

**User Story:** Jako kierownik chcę przygotowywać zakupy według braków, aby uzupełniać właściwy towar.

**What to build:** Kompletny przepływ na telefonie, przez publiczne API do trwałego zapisu i ponownego odczytu.

**Blocked by:** MM-12, MM-16

**Status:** implemented-local — odbiór natywny i urządzenie nadal otwarte.

## Kryteria odbioru

- [x] Edytowalne propozycje wynikają z progów, zapasu i rezerwacji, z widocznym uzasadnieniem.
- [x] Szkic zamówienia zakupu, zatwierdzenie i częściowe przyjęcia powiązane z dostawą.
- [x] Eksport lub świadome wysłanie przez użytkownika; brak automatycznej wiadomości do dostawcy.

## Testy i zakończenie

Testować publiczne zachowanie API z bazą i interakcje telefonu: główny scenariusz, brak uprawnień, izolację lokalu, retry i utratę połączenia tam, gdzie wpływają na wynik. TypeScript, właściwa regresja i code-review przed zakończeniem. Etap daje samodzielnie demonstracyjny rezultat; nowe schematy i interfejsy powstają razem z obsługiwanym przepływem.
