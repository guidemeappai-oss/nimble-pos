# MM-12: Dostawy i dostawcy

**User Story:** Jako kierownik chcę przyjmować dostawę telefonem, aby zwiększać zapas z prawidłowym kosztem.

**What to build:** Kompletny przepływ na telefonie, przez publiczne API do trwałego zapisu i ponownego odczytu.

**Blocked by:** MM-10a (podstawowy zasób i dziennik; integracja zestawów nie jest wymagana)

**Status:** implemented-local — kod i testy w gałęzi feat/merchant-management; bez wdrożenia. Wyniki: docs/product/stock-operations-running.md.

## Kryteria odbioru

- [x] Ilość, jednostka, dostawca i cena zakupu; wyszukiwanie i skan kodu aparatem z ręczną alternatywą.
- [x] Częściowe przyjęcie i korekta mają osobne ruchy; retry nie dubluje dostawy.
- [x] Koszt dostępny według uprawnień; dostawa odświeża dostępność.

## Testy i zakończenie

Testować publiczne zachowanie API z bazą i interakcje telefonu: główny scenariusz, brak uprawnień, izolację lokalu, retry i utratę połączenia tam, gdzie wpływają na wynik. TypeScript, właściwa regresja i code-review przed zakończeniem. Etap daje samodzielnie demonstracyjny rezultat; nowe schematy i interfejsy powstają razem z obsługiwanym przepływem.

Doprecyzowanie zależności 2026-10-16: operacje dotyczą zasobów magazynowych, więc nie wymagają jeszcze powiązania ze wszystkimi wariantami/zestawami. Automatyczny rozchód sprzedaży nadal należy do MM-11.

Granica integracji: dostawa odświeża saldo zasobu magazynowego. Automatyczna dostępność menu wymaga MM-10b/MM-11, nie jest jeszcze uruchomiona.
