# MM-10: Licznik porcji i historia zapasu

**User Story:** Jako kasjer chcę znać dostępne ilości, aby nie oferować brakującego towaru.

**What to build:** Kompletny przepływ na telefonie, przez publiczne API do trwałego zapisu i ponownego odczytu.

**Blocked by:** MM-01, MM-06

**Status:** implemented-local — MM-10a i MM-10b ukończone lokalnie; automatyczna rezerwacja i rozchód pozostają w MM-11.

## Kryteria odbioru

- [x] Wybór śledzenia sztuk/porcji lub braku śledzenia, stan otwarcia i próg ostrzeżenia.
- [x] Saldo wynika z ruchów; korekta odwraca błędny wpis z powodem, zamiast go usuwać.
- [x] Warianty i zestawy korzystają ze wspólnego zasobu, bez duplikowania ilości.

## Testy i zakończenie

Testować publiczne zachowanie API z bazą i interakcje telefonu: główny scenariusz, brak uprawnień, izolację lokalu, retry i utratę połączenia tam, gdzie wpływają na wynik. TypeScript, właściwa regresja i code-review przed zakończeniem. Etap daje samodzielnie demonstracyjny rezultat; nowe schematy i interfejsy powstają razem z obsługiwanym przepływem.
