# PL-15: Rozchód według receptury

**Zakres źródłowy:** MM-14b

**User Story:** Jako właściciel chcę otrzymać prawidłowy rozchód po sprzedaży, aby móc prowadzić lokal na podstawie spójnych danych.

**What to build:** Otrzymać prawidłowy rozchód po sprzedaży — kompletny przepływ interfejsu, API i trwałego zapisu, jeśli zadanie obejmuje funkcję.

**Blocked by:** PL-14

**Status:** implemented-local — wersjonowane receptury, jednostki, snapshoty i rozchód zintegrowane; natywny PostgreSQL i końcowy odbiór nadal otwarte.

## Kryteria odbioru

- [ ] Checkout utrwala wersję receptury, zapotrzebowanie i dostępny koszt historyczny.
- [ ] Rezerwacja i sprzedaż zużywają składniki albo gotową porcję, nigdy oba.
- [ ] Test wariantu, dodatku, zamiany, zestawu, nagrody, opóźnionej wpłaty i zwrotu.
- [ ] Zmieniona receptura nie przelicza wcześniejszych operacji.
