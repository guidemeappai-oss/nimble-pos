# PL-02: Powtarzalne środowisko natywnego PostgreSQL

**Zakres źródłowy:** MM-11 / MM-31

**User Story:** Jako właściciel chcę otrzymać wiarygodny wynik testów współbieżności, aby móc prowadzić lokal na podstawie spójnych danych.

**What to build:** Otrzymać wiarygodny wynik testów współbieżności — kompletny przepływ interfejsu, API i trwałego zapisu, jeśli zadanie obejmuje funkcję.

**Blocked by:** None — można rozpocząć

**Status:** acceptance-blocked — runner i osłony gotowe; natywny PostgreSQL odmawia startu pod jedynym dostępnym UID 0. Szczegóły: docs/product/native-postgres-running.md.

## Kryteria odbioru

- [ ] Uruchomić izolowany natywny PostgreSQL z oddzielnymi połączeniami; PGlite nie zalicza tej bramki.
- [ ] Skrypt przygotowuje bazę, migracje i dane; chroni przed uruchomieniem na bazie produkcyjnej.
- [ ] Ostatnia porcja POS/remote/nagroda, slot kolejki, retry dostawy, spis, strata i płatność kontra zwolnienie rezerwacji mają jeden prawidłowy wynik.
- [ ] Jeżeli środowisko blokuje start bazy: zapisać konkretną przeszkodę, pozostawić bramkę otwartą; nie deklarować gotowości do telefonu.

## Zakończenie

Wykonać testy ryzyk tego zadania, sprawdzić wpływ na istniejące procesy, przejrzeć zgodność z wymaganiami i standardami repozytorium. Zapisać wynik, ograniczenia i commit. Nie oznaczać testu zaliczonym na podstawie samego istnienia testu. Aktualizować status po faktycznym wykonaniu. Zależności od istniejących MM traktujemy jako lokalną bazę; odbiór urządzenia pozostaje późniejszym krokiem.
