# PL-22: Podpowiedzi zakupów i produkcji

**Zakres źródłowy:** MM-30

**User Story:** Jako właściciel chcę otrzymać uzasadnioną propozycję przygotowania, aby móc prowadzić lokal na podstawie spójnych danych.

**What to build:** Otrzymać uzasadnioną propozycję przygotowania — kompletny przepływ interfejsu, API i trwałego zapisu, jeśli zadanie obejmuje funkcję.

**Blocked by:** PL-18, PL-19, PL-21

**Status:** blocked

## Kryteria odbioru

- [ ] Wskazany okres, sprzedaż, straty, stan, rezerwacje i sposób wyliczenia.
- [ ] Mało historii daje komunikat o braku danych.
- [ ] Akceptacja użytkownika tworzy edytowalny szkic, bez samodzielnego zakupu.
- [ ] Deterministyczny test danych wejściowych i wyjaśnienia; brak scoringu pracowników.

## Zakończenie

Wykonać testy ryzyk tego zadania, sprawdzić wpływ na istniejące procesy, przejrzeć zgodność z wymaganiami i standardami repozytorium. Zapisać wynik, ograniczenia i commit. Nie oznaczać testu zaliczonym na podstawie samego istnienia testu. Aktualizować status po faktycznym wykonaniu. Zależności od istniejących MM traktujemy jako lokalną bazę; odbiór urządzenia pozostaje późniejszym krokiem.
