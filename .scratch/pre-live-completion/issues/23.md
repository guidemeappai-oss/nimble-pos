# PL-23: Pełny dzień lokalu w przeglądarce

**Zakres źródłowy:** MM-31a

**User Story:** Jako właściciel chcę przejść wszystkie procesy w jednej aplikacji, aby móc prowadzić lokal na podstawie spójnych danych.

**What to build:** Przejść wszystkie procesy w jednej aplikacji — kompletny przepływ interfejsu, API i trwałego zapisu, jeśli zadanie obejmuje funkcję.

**Blocked by:** PL-01, PL-04, PL-05, PL-06, PL-08, PL-09, PL-10, PL-11, PL-12, PL-13, PL-18, PL-19, PL-20, PL-21, PL-22

**Status:** blocked

## Kryteria odbioru

- [ ] E2E z rzeczywistym API i natywną bazą, oddzielne sesje owner/manager/cashier/customer; same dema nie wystarczą.
- [ ] Dostawa → produkcja → POS/remote → rabat → płatność → przygotowanie → odbiór → lojalność → strata → przekazanie → zamknięcie → raport.
- [ ] Drugie konto/lokal, odebranie uprawnień, restart, utrata odpowiedzi, timeout i retry.
- [ ] NIM/USDT oraz powiadomienia: kontrolowane adaptery z awariami; symulacje wyraźnie opisane.
- [ ] Spójna nawigacja mobilna, stany ładowania/błędu/puste, brak poziomego przepełnienia przy 320/390/736/1280 px; pomiar wydajności.

## Zakończenie

Wykonać testy ryzyk tego zadania, sprawdzić wpływ na istniejące procesy, przejrzeć zgodność z wymaganiami i standardami repozytorium. Zapisać wynik, ograniczenia i commit. Nie oznaczać testu zaliczonym na podstawie samego istnienia testu. Aktualizować status po faktycznym wykonaniu. Zależności od istniejących MM traktujemy jako lokalną bazę; odbiór urządzenia pozostaje późniejszym krokiem.
