# PL-18: Partie i terminy przydatności

**Zakres źródłowy:** MM-17

**User Story:** Jako kierownik chcę rozliczać zapas według partii, aby móc prowadzić lokal na podstawie spójnych danych.

**What to build:** Rozliczać zapas według partii — kompletny przepływ interfejsu, API i trwałego zapisu, jeśli zadanie obejmuje funkcję.

**Blocked by:** PL-16, PL-04

**Status:** implemented-local — odbiór natywny i urządzenie nadal otwarte.

## Kryteria odbioru

- [x] Dostawa i produkcja zapisują partie, ilości i terminy; propozycja zużycia według najbliższego terminu.
- [x] Termin daje alert/decyzję, bez kasowania salda; jawna polityka dostępności przeterminowanej partii.
- [x] Spisy, straty i rozliczenie jedzenia wskazują partie i zachowują sumy.
- [x] Migracja istniejącego zapasu nie wymyśla dat ani historii.
