# PL-25: Wydanie kandydata do testów telefonu

**Zakres źródłowy:** MM-31c

**User Story:** Jako właściciel chcę otrzymać jedną zweryfikowaną wersję aplikacji, aby móc prowadzić lokal na podstawie spójnych danych.

**What to build:** Otrzymać jedną zweryfikowaną wersję aplikacji — kompletny przepływ interfejsu, API i trwałego zapisu, jeśli zadanie obejmuje funkcję.

**Blocked by:** PL-24

**Status:** blocked

## Kryteria odbioru

- [ ] Na jednym commicie pełne testy API/web/shared, typy, build, E2E i natywna współbieżność.
- [ ] Przegląd zgodności wszystkich MM-01–30 oraz kodu; brak otwartych błędów blokujących, istotnych naruszeń danych i uprawnień.
- [ ] Macierz wymaganie → test → wynik, logi, konfiguracja, hash wersji i znane ograniczenia.
- [ ] Instrukcja uruchomienia testowej instancji z HTTPS, seed/reset i oddzielnymi danymi; samo wdrożenie opisane jako osobny krok.
- [ ] Przekazać scenariusze telefonu z wynikiem oczekiwanym i formularzem błędu; wynik GOTOWE-DO-TELEFONU dopiero po zamknięciu bramek lokalnych.

## Zakończenie

Wykonać testy ryzyk tego zadania, sprawdzić wpływ na istniejące procesy, przejrzeć zgodność z wymaganiami i standardami repozytorium. Zapisać wynik, ograniczenia i commit. Nie oznaczać testu zaliczonym na podstawie samego istnienia testu. Aktualizować status po faktycznym wykonaniu. Zależności od istniejących MM traktujemy jako lokalną bazę; odbiór urządzenia pozostaje późniejszym krokiem.
